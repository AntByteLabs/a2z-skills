Ask the same question twice and you get two answers. People read that as the
tool being unreliable. Variation alone does not establish correctness: the
answer still needs checking against the evidence. More
tool write-ups are in [AI Tools](/topics/ai-tools/). The same measurement
confusion from the other direction is in
[why AI detectors flag human writing](/ai-detectors-flagging-human-writing/),
and for systems that look consistent while being wrong, read
[why automations fail silently](/automations-failing-silently/).

## Each word is picked from a shortlist

A language model generates tokens in context. A token may be a word or part of
one. Depending on the model and its settings, generation can sample between
plausible continuations, so separate requests can produce different wording.
A product may also retrieve information through tools before composing a reply.

Where supported, settings such as temperature affect sampling. These controls
are model-specific API options, not a promise that the ChatGPT interface exposes
the same settings. Either way, one different word early on changes
what the model is continuing from, so the two answers diverge from that point
and keep diverging.

## Repeatability depends on supported controls

OpenAI's [reproducibility guidance](https://developers.openai.com/api/docs/guides/advanced-usage)
describes controls for supported API models and notes that outputs are not
guaranteed to be identical. Holding a seed fixed cannot make different models,
instructions or input histories into the same request.

The earlier version of this page offered a specific GPU arithmetic explanation
as the cause of differing replies. That was more specific than the evidence
available for an individual ChatGPT response. Without request-level evidence,
a reader cannot infer that particular cause from two different answers.

## The conversation is part of the question

Earlier messages can be part of the input for a reply. Asking a question at the
start of a chat and asking it later may therefore supply different context.
Long conversations can also involve context management, so it is too broad to
say that every message is always reread verbatim. OpenAI's
[conversation-state documentation](https://developers.openai.com/api/docs/guides/conversation-state)
explains how API applications manage the context they send.

For a product that personalises responses, saved information can add another
difference between users. Whether such information is used depends on the
product and its settings.

## The wrapper and the model both change

Every product wraps your prompt in hidden instructions about tone, format and
what to refuse. A custom assistant, a company deployment and the public website
all use different ones, so the same typed words arrive as different inputs.

Underneath, the model itself is updated. An answer you got last month may be
unreproducible today for the plain reason that the thing answering is not the
same version. If an exact output matters, save it when you get it.
