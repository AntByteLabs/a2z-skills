The download has finished, but Windows still asks for a restart. Download,
installation and completion are separate stages, so the prompt does not mean
the download failed. More explanations are in [Windows & Mac](/topics/windows-mac/).

<Callout type="note" title="Correction, 27 October 2026">
  An earlier version said every open file was locked, every slow update was disk-bound and
  interrupting an update usually required recovery media. Those claims were too broad.
</Callout>

## A completed download still leaves installation work

Microsoft's [Windows Update architecture](https://learn.microsoft.com/en-us/windows/deployment/update/how-windows-update-works)
describes scanning, downloading, installing and committing an update. The files
can already be on the computer while later stages remain unfinished.

That distinction matters when interpreting a progress indicator. A download
percentage describes that phase; it cannot promise that the desktop will be
ready after the same amount of time again. Different packages and machines
need different work. This article does not report a measured installation time
or a comparison between storage devices.

## Components in use can need a restart

A system update can affect components that Windows or its services are using.
A restart allows pending changes to finish as the system transitions to the
updated components. Microsoft's [restart guidance](https://learn.microsoft.com/en-us/windows/deployment/update/waas-restart)
explains the restart requirement and the policies that control its timing.

Open files are part of this explanation, but Windows does not lock every open
file in the same way. Sharing permissions and the operation involved matter.
Microsoft's [file-handle documentation](https://learn.microsoft.com/en-us/windows/win32/fileio/closing-and-deleting-files)
describes cases where deletion waits for handles to close and where sharing
violations prevent an operation. Those rules do not establish that every file
replacement behaves identically.

The same distinction appears in [disk space after file deletion](/deleting-files-not-freeing-disk-space/):
a name disappearing and the system releasing its storage are separate events.

## A long restart does not diagnose a failing disk

The update, the computer and the work remaining all affect duration. A single
slow restart provides too little evidence to identify a storage fault or to
promise that another machine would finish in a minute. Comparisons need the
same update and recorded conditions.

If the update shows an error, that message is more useful than assuming the
storage device caused it. Microsoft's [Windows Update FAQ](https://support.microsoft.com/en-us/windows/deployment/updates-lifecycle/windows-update-faq)
is the starting point for its supported troubleshooting guidance. The precise
symptom and Windows version determine which instructions apply.

<Callout type="warning" title="Avoid interrupting installation">
  Cutting power can interrupt pending changes. Keep the machine powered during an update. A
  stalled screen needs symptom-specific troubleshooting; elapsed time alone does not
  establish that a forced shutdown is the right action.
</Callout>

## Some changes can finish without restarting

A restart is not required for every change. Microsoft also documents
[hotpatch updates for eligible devices](https://learn.microsoft.com/en-us/windows/deployment/windows-autopatch/overview/windows-autopatch-faq).
Their availability has specific requirements, and some updates still need a
restart. A claim that all Windows updates can finish live would be as misleading
as a claim that none can.

A phone slowing down is a different diagnosis, even if it first becomes
noticeable after an update. [Phone performance](/phone-slows-down-gets-older/)
can involve an app, storage, temperature or battery behaviour as well as software.
